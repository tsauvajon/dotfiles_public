# API for Cursor

API for Cursor is the upstream `standardagents/composer-api` app. It runs a
local OpenAI-compatible server for Cursor models and stores the real Cursor API
key in the macOS app/Keychain, not in this repo.

The packaged app is Apple-Silicon/arm64-only. Enabling it on any other host
installs nothing and emits a Home Manager warning.

## Setup

1. Enable the Home Manager option from a private module:

   ```nix
   homeModules = [
     ({ ... }: { programs.apiForCursor.enable = true; })
   ];
   ```

2. Run `bash setup.sh` from this repo. On Apple Silicon, Home Manager builds
   the pinned upstream source with ad-hoc signing and creates the launcher app
   `~/Applications/API for Cursor.app` for Spotlight-compatible app launchers.
3. Open the app from Spotlight, Finder, or the `api-for-cursor` command. Enter a
   Cursor user API key from the Cursor Dashboard User API Keys page, and start
   the local API.
4. Keep the app on its default base URL: `http://127.0.0.1:8787/v1`.
5. Restart OpenCode, then select `cursorapi/composer-2.5-fast` or `cursorapi/composer-2.5`.

The app source pin, npm dependency hash, and SwiftPM Sparkle pin live in
`pkgs/api-for-cursor/default.nix` and `pkgs/api-for-cursor/generated/`.

The package intentionally builds from source. It uses upstream's development
packaging path, so the app is ad-hoc signed rather than Developer ID notarized.
The Nix build also bundles Swift runtime dylibs referenced by the app executable
into `Contents/Frameworks` and rewrites them to `@rpath`; otherwise macOS can
kill the launched app with `Code Signature Invalid` when it loads Swift runtime
libraries directly from the Nix store.

Do not use the app's OpenCode Agent Setup button for this dotfiles installation.
`~/.config/opencode/opencode.json` is generated by Home Manager, so the provider
belongs in `config/opencode/opencode.provider.cursorapi.json` and is installed
by `setup.sh`.

## Cursor API Key

Create the app key from the Cursor Dashboard User API Keys page:
https://cursor.com/dashboard/api?section=user-keys#user-api-keys. Paste that
key into the macOS app so it can store the secret in Keychain.

Do not put the real Cursor API key in this repo, in OpenCode config, or in a
Home Manager environment value. The repo-managed OpenCode provider uses the
placeholder `cursor-local`; the app replaces that placeholder with the key saved
in Keychain.

`cursor agent login` authenticates the Cursor Agent CLI, but it does not mint or
print a `crsr_...` API key for the SDK-backed API for Cursor app. If an API key
is unavailable, use the [Cursor Agent Bridge](Cursor%20Agent%20Bridge.md)
fallback instead; it authenticates through `cursor agent login` and runs Cursor
Agent subprocesses per request.

## Models

The repo-managed provider exposes the app's primary local model ids:

- `cursorapi/composer-2.5`
- `cursorapi/composer-2.5-fast`
- `cursorapi/grok-4.5`
- `cursorapi/grok-4.5-fast`

OpenCode talks to the local API using the placeholder API key `cursor-local`.
The local app ignores that placeholder and uses the Cursor API key stored
locally in the app.

## Availability And Retry Troubleshooting

Enabling `programs.apiForCursor` makes the provider available in generated
OpenCode config, but it does not prove that the app is currently running or that
its saved key is unlocked. This matters when `small_model`, a configured title
agent, or a helper agent such as `verify` uses a `cursorapi/*` model: background
title generation or verification can then make an otherwise unrelated OpenCode
operation feel slow.

Check the local service without printing credentials:

```sh
lsof -nP -iTCP:8787 -sTCP:LISTEN
curl --fail --silent --max-time 2 http://127.0.0.1:8787/v1/models >/dev/null
```

Common log errors include connection failures, SDK availability failures, and a
saved key being locked. OpenCode retries some transport/provider failures with a
backoff that reaches roughly 30 seconds, and session-level retries can continue
until cancelled. Repeated failures at that interval are retries, not active model
progress. Title generation has its own bounded retries and can still delay early
session activity.

Recovery:

- Open API for Cursor, unlock the saved key, and start the local API.
- Verify the model endpoint before retrying OpenCode work.
- Cancel a helper session that remains in a retry loop after the provider is
  known to be unavailable.
- If the app should not be a runtime dependency, disable both
  `programs.apiForCursor.enable` and the private
  `programs.opencode.providerGates.cursorapi` gate. The provider gate must define
  direct-model fallbacks for every configured `cursorapi/*` assignment. Run
  `bash setup.sh`, then inspect the generated config to confirm the assignments
  were rewritten.
- Restart the shared OpenCode server from a normal shell after generated model
  assignments change; do not restart it from an active OpenCode agent session.

See [OpenCode Debug](OpenCode%20Debug.md) for diagnosing shared-server CPU and
memory separately from local provider retries.

## Port Changes

If the app cannot bind port `8787`, either free that port and restart the app,
or override the provider in a private fragment such as
`~/.config/dotfiles/config/opencode/opencode.provider.cursorapi.json`:

```json
{
  "provider": {
    "cursorapi": {
      "options": {
        "baseURL": "http://127.0.0.1:8788/v1",
        "apiKey": "cursor-local"
      }
    }
  }
}
```

If the app itself accidentally gets saved with a different listener port, OpenCode
will keep trying `http://127.0.0.1:8787/v1` while the app listens somewhere else,
commonly `127.0.0.1:8788`. Confirm the mismatch with:

```sh
lsof -nP -iTCP -sTCP:LISTEN | rg 'API|8787|8788|8792'
curl --fail --silent http://127.0.0.1:8787/v1/models >/dev/null
curl --fail --silent http://127.0.0.1:8788/v1/models >/dev/null
```

To reset the app back to `8787`, stop it before changing preferences. The app
writes its current settings back on quit, so editing the preference while it is
running can be overwritten by the shutdown save:

```sh
osascript -e 'tell application id "ai.standardagents.cursorapi" to quit' || \
  pkill -f '/API for Cursor.app/Contents/MacOS/API for Cursor'

settings_json='{
  "backendBaseURL" : "",
  "clientVersion" : "sdk-1.0.13",
  "cursorAPIBaseURL" : "",
  "cursorAPIKey" : "",
  "launchAtLogin" : false,
  "localAgentEndpoint" : "",
  "menuBarOnly" : false,
  "port" : 8787
}'
defaults write ai.standardagents.cursorapi CursorAPI.settings.v1 \
  -data "$(printf '%s' "$settings_json" | xxd -p -c 256)"
killall cfprefsd || true
open -a "$HOME/Applications/API for Cursor.app"
```

Then verify both the OpenAI-compatible listener and the separate SDK bridge:

```sh
lsof -nP -iTCP:8787 -sTCP:LISTEN
curl --fail --silent http://127.0.0.1:8787/v1/models
curl --fail --silent http://127.0.0.1:8792/health
```

## Legacy Bridge

This replaces the default workflow for Composer in OpenCode. The older
repo-local `cursor-agent` bridge remains available as an explicit opt-in through
`programs.opencode.cursorAgentBridge.enable = true`, but it cold-starts Cursor
Agent subprocesses and is no longer the recommended path.
